how-it-works

How one question travels through OVAT

Follow the light. A question enters as a command, becomes a checked config, gets wired into an agent, and loops between the model and your tools until there is an answer. Press any step to stop on it.

Six terms, so the rest makes sense

Agent

A language model that can ask for your functions to be run. It reads the result and keeps going until it can answer.

Tool call

The model's request to run a function, written as structured text: a name plus arguments. Your code runs it, never the model.

Tool parser

The piece inside the model server that reads that text and turns it into a real call. Qwen3.5 needs qwen3coder; Qwen3 needs hermes3.

OVMS

OpenVINO Model Server. It loads the model, runs it on CPU, GPU or NPU and answers like the OpenAI API. OVAT starts and stops it for you.

openvino_genai

The library that runs a model inside your own Python process. OVAT uses it for local chat with no server, including on a Mac.

Intel AI PC

A laptop or desktop with an Intel CPU, an Arc GPU and an NPU, a chip built for AI work. OVAT routes each model to the right one.

The loop every project rewrites, replaced by a file

On the left is the smallest honest tool-calling agent against a local server, from the OVAT walkthrough. It still has no iteration cap, no error handling, no history and no server management. On the right is the same agent in OVAT.

By handPython, about 30 lines
agent.py
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v3", api_key="not-needed")

tools = [{"type": "function", "function": {
    "name": "search_docs",
    "description": "Search the user's local documents",
    "parameters": {"type": "object",
                   "properties": {"query": {"type": "string"}},
                   "required": ["query"]}}}]   # hand-written schema

messages = [{"role": "user", "content": question}]
while True:                                    # the loop, by hand
    r = client.chat.completions.create(
        model="Qwen3.5-4B-int4-ov", messages=messages,
        tools=tools, tool_choice="auto")
    choice = r.choices[0]
    if choice.finish_reason != "tool_calls":
        print(choice.message.content)
        break
    messages.append(choice.message)
    for call in choice.message.tool_calls:     # dispatch, by hand
        args = json.loads(call.function.arguments)  # may be malformed
        result = run_my_tool(call.function.name, args)
        messages.append({"role": "tool",
                         "tool_call_id": call.id,
                         "content": str(result)})
With OVATYAML, then one command
workflow.yml
model:
  name: Qwen3.5-4B-int4-ov
  device: GPU
  tool_parser: qwen3coder
tools:
  - name: search_docs
    type: builtin
agent:
  type: native
  max_iterations: 10
terminal
$ ovat serve workflow.yml
$ ovat run workflow.yml -i "what do my notes say about Q3?"
  • The loop, with a max_iterations cap so a confused model cannot spin forever.
  • Tool schemas, read from each tool's own SCHEMA, never written twice.
  • Broken tool arguments, sent back to the model as a sentence it can fix.
  • The server: ovat serve starts OVMS, --stop ends it.
  • Silent failures, like a tool call that was never decoded, named in the trace.

The loop, the tool schemas, the history, the iteration cap and the error messages become the toolkit's job. Moving from a 16 GB GPU box to an 8 GB CPU laptop is a three-line edit: compare examples/workflow.yml with examples/minimal.yml.

four-engines

Change one word, keep everything else

agent.type picks the loop that drives your tools. The model, the tools and the prompt stay the same, and all four talk to the same server through one shared description of it.
