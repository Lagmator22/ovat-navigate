Install

You need Python 3.10 to 3.14. The full agent needs Windows 11, Ubuntu 22.04 or 24.04, or RHEL 9 on x86-64, because that is where OVMS runs. macOS works for everything except serving. Plan for 8 GB of RAM at least, 16 GB to be comfortable, and about 8 GB of disk (15 GB with RAG).

terminal
$ pip install ovat

The base install already has the native engine, all built-in tools, MCP, RAG and telemetry. Extras add only what you ask for:

Optional extras

$ pip install "ovat[langchain,llamaindex,openai-agents,tui]"

Linux needs two system packages first. A minimal image has no Python, and OVMS needs libxml2. On Ubuntu: sudo apt install -y python3 python3-venv python3-pip libxml2 curl. On RHEL 9: sudo dnf install -y python3 python3-pip libxml2 curl.

Using a GPU or NPU? Update the driver first. An old driver usually shows up as the device being missing from ovat doctor, not as an error. On Windows also install the Visual C++ Redistributable, which OVMS needs to start at all.

Your first run

  1. Install the model server, once

    $ ovat setup

    Picks the right OVMS archive for your OS, checks its SHA-256, and unpacks it into ~/.ovat/ovms. No PATH edit, no environment variable. Running it again does nothing. On macOS it explains that there is no build and what to use instead.

  2. Write a starter config

    $ ovat init workflow.yml

    Writes a workflow.yml tuned to this machine, with the device it detected.

  3. Check the machine and the config

    $ ovat doctor workflow.yml

    A table of checks: Python, dependencies, OpenVINO devices, device routing, OVMS, and your config. Green is fine, yellow is a heads-up with the fix written next to it, red needs fixing.

  4. Prove the wiring, with no server

    $ ovat run workflow.yml --dry-run
Built agent  model=Qwen3.5-4B-int4-ov  tools=['search_docs', 'transcribe']  max_iterations=10
dry-run: not calling the model.

    Builds the whole agent and stops before calling the model. Works on any machine, including a Mac.

  5. Start OVMS

    $ ovat serve workflow.yml

    The first time, this downloads the model: 3.5 GB for the default. It shows elapsed time and only gives up after five minutes with no progress at all, so a slow connection is fine. When OVMS is ready, the prompt comes back and the server keeps running in the background. Its process ID is saved in ovms.pid and its log in ovms.log.

  6. Ask something

    $ ovat run workflow.yml -i "summarise my notes"

    The first line says which engine ran. Then comes the answer, and, when a document search ran, a sources: line that OVAT prints from the tool results itself. Add --react, --llamaindex or --openai-sdk to try another engine without editing the file.

  7. Give it your documents

    # the embedder is the one model you convert yourself
$ pip install "ovat[convert]"
$ optimum-cli export openvino --model BAAI/bge-small-en-v1.5 \
    --task feature-extraction models/bge-small-en-v1.5

$ ovat index ./my-notes workflow.yml

    Reads every .txt and .md file in the folder, slices it into chunks, embeds them and stores them in the file named by rag.retriever.db_path. Run it again after editing documents: run and chat warn when an indexed file has changed or gone.

  8. Shut it down

    $ ovat serve workflow.yml --stop

    Stops the OVMS that serve started, after checking the saved process really is OVMS.

On a Mac: chat locally, no server

OVMS has no macOS build. openvino_genai does run natively on Apple Silicon, so ovat chat gives you real retrieval-augmented answers on the CPU: it embeds your question, pulls the closest chunks from your index, and has a local model answer from them. It does not call tools; it always retrieves first and then answers once.

macOS, from a clone of the OVAT repo
$ git clone https://github.com/Lagmator22/ovat.git && cd ovat
$ hf download OpenVINO/Qwen3.5-0.8B-int4-ov --local-dir models/Qwen3.5-0.8B-int4-ov
$ pip install "ovat[convert]"
$ optimum-cli export openvino --model BAAI/bge-small-en-v1.5 \
    --task feature-extraction models/bge-small-en-v1.5
$ ovat index ./examples/rag/docs examples/rag/workflow.yml
$ ovat chat examples/rag/workflow.yml -i "What is OVAT's memory budget?"

ovat chat finds a local model by itself (in model_search_paths, OVAT_MODELS, ./models and ~/models), or take one with --model-path. It streams the answer; Ctrl-C stops it. There is no answer length cap unless you set --max-tokens.

Compare the four engines

terminal
$ ovat bench workflow.yml -i "What can you do?" --out report.json
$ ovat bench workflow.yml -i "..." --repeat 5     # success rate and medians

Each engine runs in its own fresh process, so one engine's memory does not leak into the next one's number. A failing engine becomes a row with the reason written under the table, not a crash.

Traces and telemetry

terminal
$ ovat run workflow.yml -i "..." --trace trace.json        # one run: turns, tokens, tools, latency
$ ovat run workflow.yml -i "..." --telemetry live.jsonl  # sampled while it runs
$ ovat telemetry                                            # the machine, live, no run

The trace records every turn: the tool calls with their sources, token counts, latency, and the failure flags (truncated, undecoded_tool_call, empty_answer). A failed run still writes its trace and exits non-zero. Unknown values stay null, never 0.

One caveat on memory: --trace measures the OVAT process. With OVMS serving, the model lives in the server process. For Qwen3.5-4B that was measured at 4.3 GB steady and 6.5 GB peak, while the trace said about 0.45 GB. On the local ovat chat path the trace is the model.

The terminal UI

Install the tui extra, then run ovat with no arguments. Anything you type runs as a real command in your environment; typing / opens a menu of OVAT shortcuts. Chat runs inside the app: the model loads once, answers stream, and conversations are saved in .ovat/sessions/.

Writing workflow.yml

Four sections: model (required), tools, agent and rag. Unknown keys are errors, so a typo fails immediately. Select a line or a note to see what it does. Every field, with its type and default, is in the generated reference.

Name your tool parser. The wrong one fails silently: the agent answers fluently and never calls a tool. If you leave the field out, OVAT derives it from the model name, and falls back to hermes3 for families it does not know.

Adding an MCP tool

Any MCP server that speaks over stdio becomes a tool with a few lines of YAML. OVAT launches it, asks which tools it offers, and imports every one of them. Here is a tool of your own, written with FastMCP, the same library OVAT's built-ins use.

my_tool.py
from fastmcp import FastMCP

mcp = FastMCP("word_count")


@mcp.tool
def word_count(path: str) -> int:
    """Count the words in a text file.
    Use when the user asks how long a file is."""
    with open(path, encoding="utf-8") as f:
        return len(f.read().split())


if __name__ == "__main__":
    mcp.run()
workflow.yml
tools:
  - name: word_count
    type: mcp_stdio
    command: ["python", "my_tool.py"]

  # someone else's server, from npm
  - name: filesystem
    type: mcp_stdio
    command: ["npx", "-y",
      "@modelcontextprotocol/server-filesystem", "/docs"]

The docstring is for the model. It reads the description to decide when to call your tool, so say plainly when to use it.

Environment. An MCP server starts with only a few variables (HOME, PATH and a handful more). Pass anything else with env: under the tool; ${VAR} is expanded from your shell.

It works the other way too. OVAT's own tools are MCP servers: python -m ovat.tools.transcribe gives any MCP-aware agent OpenVINO Whisper, and python -m ovat.tools.search_docs --config workflow.yml serves your index.

These are ready-made OpenVINO exports on Hugging Face. ovat serve downloads the one in source_model; on a Mac fetch it with hf download.

Only the Qwen3.5-4B memory figure was measured, on an Intel AI PC, from the OVMS process. The others are estimates from parameter count and precision. The load spike decides whether a model fits, so 8 GB machines should prefer the 0.8B model.

Troubleshooting

Symptoms and likely causes
SymptomLikely cause
The agent answers fluently but never calls a toolWrong tool_parser. Qwen3.5 needs qwen3coder, Qwen3 needs hermes3. OVAT warns when raw tool-call markup reaches the answer.
OVMS exited without becoming ready, empty logThe python_off build, or a missing VC++ Redistributable on Windows.
ovat doctor finds no OVMSSet OVAT_OVMS to the unpacked folder, or run ovat setup.
No GPU or NPU listed in doctorThe driver is out of date.
search_docs returns [stub]No rag: section, or no --config on the MCP command.
serve looks stuckThe first run downloads the model. Watch ovms.log.
A request times out on a CPU-only machineRaise model.request_timeout; an agent turn is several model calls. OVAT says this when it happens.
